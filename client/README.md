# Веб-клиент Jacko

Svelte 5, TypeScript и Vite. Требуется Node.js 20.19+ из ветки 20 или 22.12+.

Запустите API и инфраструктуру по [серверной инструкции](../docs/server-foundation.md#запуск-http-api). Для сценария с регистрацией и немедленным входом используйте локальный режим без SMTP.

```sh
cd client
npm ci
npm run dev
```

Откройте адрес, который напечатал Vite. По умолчанию Vite проксирует HTTP и WebSocket на `http://127.0.0.1:8080`. Для другого локального API задайте `JACKO_API_TARGET`. Production-сборку из `dist/` нужно отдавать с возвратом `index.html` для маршрутов приложения и проксированием `/api/v1` с поддержкой WebSocket Upgrade на том же origin.

## Маршруты

| Путь | Экран |
|---|---|
| `/` | Список сообществ и создание первого сообщества |
| `/login`, `/register` | Вход и регистрация с возвратом в канал или к приглашению через `next` |
| `/verify`, `/forgot` | Подтверждение почты и восстановление пароля в почтовом режиме |
| `/invite/:token` | Подтверждение приглашения и переход к каналам сообщества |
| `/guilds/:id` | Список каналов и действия сообщества |
| `/guilds/:id/channels/:channel` | История и поле отправки выбранного канала |

Списки и история показывают загрузку, пустой результат и ошибки. В чате видны восстановление подключения и ошибки отправки. На узком экране из канала можно вернуться к списку каналов. Токены живут в памяти вкладки, после обновления страницы нужно войти снова. IndexedDB хранит историю и курсор отдельно для каждого аккаунта. Лимит составляет 8 каналов, до 200 сообщений и до 512 КиБ данных сообщений на канал. После проверки доступа через WebSocket клиент восстанавливает историю и позицию. Выход очищает кэш текущего аккаунта.

```sh
npm run check
npm run build
npm run generate:api  # после изменений в OpenAPI
```

Для ручной проверки зарегистрируйте два аккаунта в независимых браузерных контекстах. В первом создайте сообщество и откройте приглашение во втором. В обоих откройте канал `general` и отправьте по сообщению. Отключите сеть у одного браузера, отправьте ещё одно сообщение из другого и восстановите сеть. Сообщение должно появиться один раз.

Для проверки вложений запустите API с `JACKO_S3_URL`, доступным из браузера. Хранилище должно разрешать multipart POST с origin клиента. В канале можно отправить JPEG или PNG до 8 МиБ с необязательной подписью. Проверьте, что второй аккаунт видит изображение, а после удаления сообщения ссылка через API больше не выдаётся.

Для проверки почтовых сценариев установите `JACKO_SMTP_ADDR=127.0.0.1:1025` и `JACKO_SMTP_FROM=jacko@example.test` при запуске API. Код из [Mailpit](http://127.0.0.1:8025) вводится на экране подтверждения почты или восстановления пароля. В канале участник может пожаловаться на чужое сообщение. Список жалоб и решения доступны владельцу в разделе «Жалобы» сообщества.
