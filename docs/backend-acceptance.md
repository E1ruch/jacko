# Приёмка бэкенда Jacko

Дата проверки — 12 ноября 2026. API, клиенты нагрузки и контейнеры PostgreSQL, Redis и S3 работали на одной машине. Отказы и восстановление проверены на временных ресурсах отдельно от основного API.

| Проверка | Результат |
|---|---|
| Интеграционный прогон | `server/scripts/test-api.sh` завершился успешно. Тесты с `-race`, `go vet` и `govulncheck` прошли. |
| Остановка Redis | HTTP продолжил сохранять сообщения и отдавать историю. Список участников вернулся с неизвестным онлайн-статусом. После запуска Redis клиент восстановил сообщение по курсору. |
| Недоступный S3 | Завершение загрузки вернуло HTTP 503. После ошибки API принял текстовое сообщение. |
| Восстановление PostgreSQL | Полный дамп схемы восстановился в отдельную БД. Строки и значения последовательностей совпали с дампом. |
| Восстановление S3 | Один объект из манифеста восстановленной БД перенесён из локальной копии в отдельный бакет. Размер, SHA-256 и MIME-тип совпали. |
| Нагрузка, 32 клиента | 8 отправителей, 200 сообщений, 6 400 доставок. p99 от начала HTTP-запроса до чтения WebSocket составил 63 мс в прогоне с `-race`. |
| Нагрузка, 10 000 клиентов | Один шлюз удержал подключения 21 секунду после завершения подключения. Пять сообщений в один канал дали 50 000 доставок по порядку в каждом прогоне. p99 по трём прогонам — 354, 445 и 231 мс. Цель 300 мс выполнена в одном из трёх прогонов. |

## Как повторить нагрузку

Из корня проекта, с запущенным Docker Compose:

```sh
./server/scripts/test-api.sh
cd server
JACKO_TEST_DATABASE_URL='postgres://jacko:jacko@127.0.0.1:5432/jacko?sslmode=disable' \
JACKO_TEST_REDIS_URL='redis://127.0.0.1:6379/0' \
JACKO_TEST_WS_CAPACITY=10000 go test -run '^TestGatewayCapacity$' -count=1 -v ./internal/messages/postgres
```

Тест создаёт собственную схему PostgreSQL и тему Redis. Для каждого клиента создаются отдельная сессия и членство. Измеряется время от начала HTTP-запроса до чтения события из WebSocket. Цель архитектуры — p99 ниже 300 мс внутри региона. Локальная приёмка завершена. При росте задержек смотрим метрики HTTP, outbox и WebSocket в Prometheus. После появления веб-клиента отдельно измерим время до отрисовки. [Метрики стенда](server-foundation.md#метрики-стенда)

## Как проверить восстановление

Сохраните полный дамп PostgreSQL в закрытом каталоге. Восстановите его в новую временную БД через `pg_restore --clean --if-exists --exit-on-error --single-transaction`, указав эту БД в `-d`. Используйте полный дамп: сообщения могут ссылаться на другие сообщения, и загрузка только данных в таблицы с активными внешними ключами зависит от порядка строк. Сравните восстановленные данные и значения последовательностей с дампом.

Из восстановленной БД получите ключи `attachments.object_key` для завершённых вложений. Восстановите соответствующие объекты из копии в отдельный бакет, сохраняя ключи и MIME-типы. Сверьте размер и SHA-256. Для приёмки резервирования на бете повторите сценарий на отдельном хранилище и проверьте запуск API с восстановленной парой БД и бакета. Локальный прогон проверил восстановление одного файла.
